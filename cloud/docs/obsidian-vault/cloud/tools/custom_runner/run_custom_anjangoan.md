# Run Custom Anjangoan

## Purpose

This script is a powerful, configurable tool for running the scheduling engine for a specific site (`Anjangoan` by default) and date. It allows for detailed control over the inputs and execution flow, making it ideal for development, testing, and debugging the scheduling logic.

It can simulate various scenarios, such as:
- Triggering scheduling runs for specific 15-minute blocks.
- Using different intraday forecast files for different runs.
- Skipping the data fetching step to use local, pre-existing data.
- Generating a final "frozen" schedule that simulates the real-world, progressive revision process throughout the day.

## Configuration

This script is primarily configured by editing the `CUSTOM RUN CONFIG` section directly within the file. This design choice allows for complex configurations that would be cumbersome to pass as command-line arguments.

| Variable                  | Type          | Description                                                                                                                              |
| :------------------------ | :------------ | :--------------------------------------------------------------------------------------------------------------------------------------- |
| `SITE_ID`                 | `str`         | The target site ID. Defaults to `Anjangoan`.                                                                                             |
| `CUSTOM_DATE`             | `str`         | The target date in `YYYY-MM-DD` format.                                                                                                  |
| `CUSTOM_START_BLOCKS`     | `list[int]`   | A list of one or more starting blocks (1-96) to trigger scheduling runs for.                                                             |
| `SKIP_FETCH`              | `bool`        | If `True`, the script will use existing data in `custom/input` instead of fetching new data.                                             |
| `INTRADAY_FILE_NAME`      | `str`         | (Optional) The exact filename of an intraday forecast CSV from `custom/input/<SITE>/<DATE>/enercast_data/intraday` to use for the run.     |
| `INTRADAY_FILE_NAMES`     | `list[str]`   | (Optional) A list of filenames to simulate multiple, sequential intraday revisions.                                                      |
| `INTRADAY_SELECTION_MODE` | `str`         | How to select the intraday forecast file: `all` (run for every file), `prompt` (interactive), `latest`, or `configured` (use the variables above). |

## Execution Flow

1.  **Configuration Validation**: The script first validates the settings in the `CUSTOM RUN CONFIG` section.
2.  **Data Fetching (Optional)**: If `SKIP_FETCH` is `False`, it invokes `[[custom_fetch_anjangoan.py]]` to download the required input data (forecasts, metered data, etc.) into the `custom/input` directory.
3.  **Intraday File Selection**: It determines which intraday forecast CSV file(s) to use based on the `INTRADAY_SELECTION_MODE`. This allows for simulating runs with different forecast versions.
4.  **Engine Invocation Loop**: The script iterates through each `CUSTOM_START_BLOCKS` and each selected intraday file. In each iteration, it:
    a.  Constructs an `event` payload that mimics the JSON event passed to an AWS Lambda function. This payload contains all the necessary context for the run, including date, block, and paths to the custom input/output directories.
    b.  Calls the `run` function from the `[[fetcher_engine.py]]` module, which is the primary entry point for the entire scheduling process.
5.  **Final Schedule Reduction**: After all individual runs are complete, the `_reduce_final_frozen_schedule` function is called. This function is critical for simulating a real day's operations. It scans all the generated partial schedules and intelligently combines them into a single, coherent "frozen" schedule for the entire day. For each 15-minute block, it chooses the schedule that was generated by the latest relevant run (i.e., the run whose effective timestamp was just before or at that block's time).
6.  **Graph Generation**: Finally, it generates a plot visualizing the final frozen schedule, the latest intraday forecast, and the actual metered data. This graph is saved to the `custom/output` directory for analysis.

## Key Functions

-   `main()`: The main entry point that orchestrates the entire process.
-   `_select_intraday_file_interactive()`: Provides an interactive command-line prompt for the user to select a specific intraday forecast file from the available options.
-   `_reduce_final_frozen_schedule()`: This is a core function that simulates the progressive nature of scheduling. It takes all the partial schedules generated throughout the simulated day and creates a single, final schedule that reflects the decisions that would have been made at each point in time.
-   `_load_intraday_graph_df()` / `_load_graph_inputs()`: Helper functions for loading and parsing data from various CSV formats into pandas DataFrames for graphing.
